## Business Context
A factory sources raw materials and components from **foreign suppliers**. Each purchase quote comes
in the **supplier's own currency**. To compare quotes and control spend, the procurement team needs
every quote converted to the company's **base currency** (e.g., USD) using **live exchange rates**,
and each quote flagged as within or over budget. Exchange rates must be **cached** (don't call the
API on every screen refresh) and the app must **still work if the rate API is temporarily down**.

**External open API:** [Frankfurter](https://frankfurter.dev) — free, **no API key** (ECB rates).
```
GET https://api.frankfurter.app/latest?from={base}&to={currency}
    e.g. .../latest?from=USD&to=IDR,KRW,EUR
    → { "base":"USD", "date":"2026-09-03", "rates": { "IDR":16250.0, "KRW":1360.5, ... } }
```
*If setup blocks you, any free open API is fine — note your choice in the README.*

**Compute rule (use exactly this):**
`converted_amount` = `quote_amount` × rate(`quote_currency` → `base_currency`).
→ if `converted_amount > budget_amount` then **OVER_BUDGET**, else **WITHIN_BUDGET**.

## High-Level Architecture

```
                 ┌──────────────────────────┐
                 │   React SPA (Procurement) │
                 │ quote board + budget flag │
                 └───────────┬──────────────┘
                             │ REST (JSON)
                             ▼
                 ┌──────────────────────────┐
                 │       Quote Service       │  Spring Boot
                 │ CRUD quotes, convert+flag │
                 └────┬───────────────┬─────┘
                      │ JPA/DB        │ (internal call)
                      │               ▼
                      │   ┌──────────────────────────┐
                      │   │   FX / Conversion logic    │  own package/class
                      │   │ fetch + cache + convert     │ (bonus: separate service)
                      │   └───┬──────────────────┬────┘
                      │       │ JPA/DB           │ HTTP
                      ▼       ▼                  ▼
                 ┌────────────────────┐   ┌──────────────────┐
                 │  Relational DB     │   │  Frankfurter API │
                 │ purchase_quote,    │   │ (external open)  │
                 │ fx_rate_cache      │   └──────────────────┘
                 └────────────────────┘
```

| Component | Owns | Key behavior |
|-----------|------|--------------|
| **React SPA** | UI | Quote board (list + create form); WITHIN_BUDGET / OVER_BUDGET flag; loading/error states |
| **Quote Service** | `purchase_quote` table | Create + list quotes; converts amount and sets the budget flag |
| **FX / Conversion logic** | `fx_rate_cache` table | Calls Frankfurter; caches rates by currency pair/date; converts; serves cache on external failure. *Bonus: extract into its own service.* |
| **Relational DB** | Persistence | `purchase_quote`, `fx_rate_cache` (rate + `fetched_at`) |
| **Frankfurter** | — | Source of exchange rates |

> **Default (expected):** build this as a **single Spring Boot app (monolith)** — keep the FX/conversion
> logic in its own package/class so the boundary is visible.
> **Bonus:** split into a separate **FX Service** talking over REST. A clean monolith with a clear
> boundary counts almost as much as an actual split — be ready to explain **where you'd split it**.

## Suggested Schema (Oracle syntax — adapt to your database)

```sql
CREATE TABLE purchase_quote (
  id               NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  supplier_name    VARCHAR2(100) NOT NULL,
  item_code        VARCHAR2(50)  NOT NULL,
  quote_amount     NUMBER(14,2)  NOT NULL,
  quote_currency   VARCHAR2(3)   NOT NULL,   -- e.g. KRW, EUR, IDR
  base_currency    VARCHAR2(3)   DEFAULT 'USD',
  budget_amount    NUMBER(14,2)  NOT NULL,   -- in base currency
  converted_amount NUMBER(14,2),
  budget_flag      VARCHAR2(15),             -- WITHIN_BUDGET / OVER_BUDGET / UNKNOWN
  created_at       TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE fx_rate_cache (
  id               NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  base_currency    VARCHAR2(3)   NOT NULL,
  target_currency  VARCHAR2(3)   NOT NULL,
  rate             NUMBER(18,6)  NOT NULL,
  rate_date        DATE          NOT NULL,
  fetched_at       TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
);
```

> **Database is optional / your choice.** Oracle is preferred but **not required** — you may use any
> relational database (PostgreSQL, MySQL, H2, etc.). Use equivalent DDL and keep the columns the same.
> Note your choice in the README.
> You may add additional column if your logic required it. Explain it in the README.

## What to Build — Prioritized (do P0 first)

### P0 — Required (minimum to pass — aim to finish these first)
- Create + list purchase quotes (REST + your database), with basic validation and 404 on a missing id.
- Fetch the exchange rate from the open API for the quote's currency → base currency.
- Cache rates in the DB; only call the API when that currency pair/day isn't cached (or is stale).
- Compute the converted amount + WITHIN_BUDGET / OVER_BUDGET flag and show it per quote in a React board (list + create form).
- If the rate API is down, still load the board (use cached rates, or flag `UNKNOWN`) — don't crash.

### P1 — Nice to Have
- Provide a `docker-compose.yml` that starts the dev environment (at least the database) so it runs with a single `docker compose up`.
- Update / delete quotes.
- Filter quotes by supplier, currency, or budget flag.
- Show the rate used + fetch time behind each converted amount.

### P2 — Bonus (plus points — only if time)
- Additional features that hasn't been mentioned above.
- Unit tests for the conversion logic and the cache-fallback path.
- Compare multiple quotes for the same item and mark the cheapest (in base currency).
- **Full-stack Docker Compose** — app + database (+ any split services) all started with one `docker compose up`.
