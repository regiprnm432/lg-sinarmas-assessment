# Supplier Quote Comparison with Currency Conversion (Case A-002)

A full-stack procurement comparison platform built with **Java 17**, **Spring Boot 3**, **React**, and a relational database. It enables procurement teams to evaluate supplier quotes from across the globe in various foreign currencies (e.g. KRW, EUR, IDR) by converting them into the company's base currency (**USD**) using live exchange rates and flagging whether each quote is within or over budget.

---

## 🏛️ Architecture Overview

The system is structured as a **clean monolith** with a strict boundary between two independent domain modules, making future microservice extraction straightforward:

```
                      ┌────────────────────────────────────────┐
                      │        React SPA (Procurement)         │
                      │  Quote Board + Budget Flags + Filters  │
                      └───────────────────┬────────────────────┘
                                          │ REST (JSON)
                                          ▼
                      ┌────────────────────────────────────────┐
                      │             Quote Service              │  Spring Boot
                      │  CRUD Quotes, Best Value Comparison    │  (com.procurement.fx.quote)
                      └─────────┬────────────────────┬─────────┘
                                │ JPA/DB             │ (internal call)
                                │                    ▼
                                │        ┌────────────────────────────┐
                                │        │   FX / Conversion Logic    │  (com.procurement.fx.fx)
                                │        │ Fetch, Cache, Convert, DB  │  isolated package
                                │        └─────┬────────────────┬─────┘
                                │              │ JPA/DB         │ HTTP
                                ▼              ▼                ▼
                      ┌──────────────────────────────────┐    ┌───────────────────────┐
                      │          Relational DB           │    │    Frankfurter API    │
                      │  purchase_quote, fx_rate_cache   │    │  (ECB Live FX Rates)  │
                      └──────────────────────────────────┘    └───────────────────────┘
```

### Module Responsibilities:
- **`com.procurement.fx.quote`**: Owns the `purchase_quote` table. Manages CRUD operations, validates incoming quotes, checks converted totals against budgets (`WITHIN_BUDGET` / `OVER_BUDGET` / `UNKNOWN`), and identifies the cheapest quote per item code.
- **`com.procurement.fx.fx`**: Owns the `fx_rate_cache` table. Interfaces with Frankfurter open API, stores daily exchange rate snapshots, and serves cached rates to guarantee resilience if the external API becomes temporarily unavailable.

## 🗄️ Database Strategy & Schema

### Database Choice:
- **Oracle Compatibility**: As requested in the brief (*"Oracle is preferred but not required"*), the data model is fully compatible with Oracle Database. The official Oracle DDL script is provided in [`backend/src/main/resources/schema-oracle.sql`](backend/src/main/resources/schema-oracle.sql).
- **Evaluation & Local Dev (H2)**: To ensure **zero-setup, instant execution** for reviewers within the assessment time window, the default profile uses **H2 in-memory/file** with a built-in web console at `http://localhost:8080/h2-console`.
- **Containerized Deployment (PostgreSQL)**: For Dockerized execution, a production-grade PostgreSQL service is configured in `docker-compose.yml` (`application-docker.yml`).

### Schema Definition:
```sql
CREATE TABLE purchase_quote (
  id               BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  supplier_name    VARCHAR(100)  NOT NULL,
  item_code        VARCHAR(50)   NOT NULL,
  quote_amount     NUMERIC(14,2) NOT NULL,
  quote_currency   VARCHAR(3)    NOT NULL,
  base_currency    VARCHAR(3)    DEFAULT 'USD',
  budget_amount    NUMERIC(14,2) NOT NULL,
  converted_amount NUMERIC(14,2),
  budget_flag      VARCHAR(15),             -- WITHIN_BUDGET / OVER_BUDGET / UNKNOWN
  rate_used        NUMERIC(18,6),            -- [Additional column] Historical rate snapshot
  rate_fetched_at  TIMESTAMP,               -- [Additional column] Exact time rate was captured
  created_at       TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE fx_rate_cache (
  id               BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  base_currency    VARCHAR(3)    NOT NULL,
  target_currency  VARCHAR(3)    NOT NULL,
  rate             NUMERIC(18,6) NOT NULL,
  rate_date        DATE          NOT NULL,
  fetched_at       TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
);
```

> **Note on Additional Columns:**
> - `rate_used` and `rate_fetched_at` were added to `purchase_quote` to satisfy the **P1 requirement** (*"Show the rate used + fetch time behind each converted amount"*). This creates an immutable audit trail of the exact conversion rate at the time of quotation.

## 🌐 External Exchange Rate API (Frankfurter)

- **Provider**: [Frankfurter API](https://frankfurter.dev) (European Central Bank data, free, no API key).
- **Endpoint**: `https://api.frankfurter.dev/v1/latest?from={quoteCurrency}&to={baseCurrency}`.
- **Conversion Rule**:
  $$\text{converted\_amount} = \text{quote\_amount} \times \text{rate}(\text{quote\_currency} \to \text{base\_currency})$$
- **Resilience & Caching Workflow**:
  1. If `quote_currency == base_currency` (e.g. USD to USD), rate is `1.0` immediately without API/DB lookup.
  2. If today's rate is already cached in `fx_rate_cache`, it is reused directly (no external network call).
  3. If missing, the app queries Frankfurter and saves the rate into `fx_rate_cache`.
  4. **Fallback on Failure**: If Frankfurter is unreachable or times out:
     - The app checks for the latest historical cached rate for that pair in `fx_rate_cache`.
     - If no historical rate exists, the quote is safely marked as **`UNKNOWN`** without crashing the application.

## 🚀 How to Run

### Method 1: Local Development (Instant, Zero Setup)

#### Prerequisites:
- Java 17+ and Maven 3.8+
- Node.js 18+ and npm

#### 1. Start the Backend:
```bash
cd backend
mvn spring-boot:run
```
* Backend runs on: `http://localhost:8080`
* H2 Database Console: `http://localhost:8080/h2-console` (JDBC URL: `jdbc:h2:mem:procurement_fx`, User: `sa`, Password: *(leave blank)*)

#### 2. Start the Frontend:
```bash
cd frontend
npm install
npm run dev
```
* Access the web interface at: `http://localhost:5173`

---

### Method 2: Docker Compose (Full Stack)

To run the complete stack (PostgreSQL + Spring Boot backend + React Nginx frontend) with one command:
```bash
docker compose up --build
```
* **Frontend UI**: `http://localhost:3000`
* **Backend REST API**: `http://localhost:8080/api/quotes`
* **PostgreSQL Database**: `localhost:5432`

## 📡 REST API & Interactive Swagger Documentation

Interactive OpenAPI 3 / Swagger documentation is available out of the box:
- **Swagger UI**: [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html) *(or [http://localhost:3000/swagger-ui/index.html](http://localhost:3000/swagger-ui/index.html) under Docker)*
- **OpenAPI JSON Spec**: [http://localhost:8080/v3/api-docs](http://localhost:8080/v3/api-docs)

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/quotes` | List quotes (supports `supplier`, `currency`, `budgetFlag`, `itemCode` query params) |
| `GET` | `/api/quotes/{id}` | Get quote details by ID (returns `404` if not found) |
| `POST` | `/api/quotes` | Create quote, convert FX, evaluate budget flag (`201 Created`) |
| `PUT` | `/api/quotes/{id}` | Update existing quote and recalculate conversion |
| `DELETE` | `/api/quotes/{id}` | Delete quote (`204 No Content`) |
| `POST` | `/api/quotes/recalculate` | Re-fetch live rates and re-convert all quotes in bulk |
| `GET` | `/api/quotes/rates` | Inspect live contents of `fx_rate_cache` table |

### Sample `POST /api/quotes` Request:
```bash
curl -X POST http://localhost:8080/api/quotes \
  -H "Content-Type: application/json" \
  -d '{
    "supplierName": "Samsung SDI Cheonan",
    "itemCode": "OLED-PANEL-55",
    "quoteAmount": 380000.00,
    "quoteCurrency": "KRW",
    "baseCurrency": "USD",
    "budgetAmount": 280.00
  }'
```
